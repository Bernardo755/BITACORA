BITÁCORA INTELIGENTE DE TRÁMITES
ARQUITECTURA MODULAR: GITHUB PAGES + CLOUDFLARE WORKER + GOOGLE APPS SCRIPT

ESTRUCTURA
- index.html: estructura HTML, sin CSS ni lógica JavaScript incrustada.
- css/estilos.css: estilos de la interfaz.
- js/config.js: URL pública del Worker (único dato de conexión que requiere el navegador).
- js/api.js: capa de comunicación HTTP JSON con el Worker.
- js/app.js: eventos, navegación y comportamiento visual.
- Code.gs: lógica de negocio, autenticación, validaciones, consultas y operaciones con Sheets.
- worker.js: proxy HTTP entre GitHub Pages y Apps Script, incluyendo CORS.

1. GOOGLE APPS SCRIPT
1) Abre el proyecto de Apps Script y pega el contenido completo de Code.gs.
2) Configura los IDs de las hojas de cálculo en CFG, al inicio del archivo.
3) Ejecuta configurarSistema() y autoriza los permisos.
4) Configura crearPrimerAdministrador() con usuario, nombre y contraseña segura; ejecútala una sola vez.
5) Implementa como Aplicación web, ejecutando como tú. El Worker debe poder acceder al endpoint /exec; configura el acceso de la implementación de acuerdo con la política institucional. Copia la URL /exec.
6) No publiques ni coloques la URL /exec en el HTML o en GitHub.

2. CLOUDFLARE WORKER
1) Crea un Worker y pega worker.js.
2) Configura estas variables:
   GAS_EXEC_URL = URL completa de la implementación Apps Script terminada en /exec.
   ALLOWED_ORIGIN = origen exacto del sitio GitHub Pages, por ejemplo https://usuario.github.io.
3) Publica el Worker y copia su URL workers.dev.

3. GITHUB PAGES
1) Abre js/config.js.
2) Sustituye https://TU-WORKER.TU-SUBDOMINIO.workers.dev por la URL real de tu Worker.
3) Sube toda la carpeta del proyecto al repositorio, respetando las carpetas css y js.
4) Activa GitHub Pages desde Settings > Pages.
5) Prueba el inicio de sesión y después el registro, comparador, alertas y expedientes.

COMUNICACIÓN
El navegador envía solicitudes POST con JSON al Worker. El Worker reenvía el contenido al endpoint /exec de Apps Script. Apps Script ejecuta doPost(e) y devuelve JSON. No se utiliza google.script.run.
El navegador no conoce la URL /exec ni las credenciales de servidor.

ACCIONES API
login, logout, bootstrap, registrarAtencion, compararBase, alertas, resolverAlerta, agregarTramite, crearUsuario, buscarPersonas, obtenerExpediente.

SEGURIDAD
- Las contraseñas se derivan en Apps Script con PBKDF2-HMAC-SHA256, sal individual y pepper guardado en Script Properties (según el código del proyecto).
- El token de sesión se valida en el servidor en las operaciones protegidas.
- No se almacena el token en localStorage ni sessionStorage.
- ALLOWED_ORIGIN/CORS no es autenticación: un cliente no navegador puede falsificar Origin. La autenticación efectiva es la validación de sesión en Code.gs.
- Para información personal (CURP, teléfono y correo), aplica acceso restringido, auditoría, límites de solicitudes y políticas institucionales. Se recomienda añadir un secreto servidor-a-servidor Worker->Apps Script y rate limiting antes de uso productivo.
- La sesión expira a los 60 minutos. El aviso de 5 minutos es visual; el código actual no concede una gracia real para guardar después del vencimiento.

NOTAS
- No pongas claves, pepper, contraseñas ni GAS_EXEC_URL en GitHub Pages.
- config.js contiene la URL del Worker y por tanto es visible públicamente; eso es esperado.
- Si cambias la estructura de carpetas, actualiza las rutas de los archivos CSS/JS en index.html.
- Un GET directo al Worker puede responder 405; la prueba real se hace iniciando sesión desde la página.
